# Global instructions

Software engineering, fullstack web.

## Code comments

Keep comments short and focused on the code. Comments explain the code, not the change that introduced it.

- **Keep them brief** — one or two lines, three at most. If more is needed, the
  code wants refactoring or a doc comment, not a wall of inline commentary.
- **Describe the scenario, not the PR** — say what the code handles, or why it
  exists, in terms a future reader needs. No PR numbers, issue numbers or
  ticket IDs; the scenario should be clear without chasing external links.
